# Миграция данных

Остановите старый бот и сделайте консистентную копию SQLite. Не запускайте старую
и новую версии на одной БД одновременно. Сначала проверьте миграцию на копии.
Команда использует только DATABASE_URL/DB_PATH, не требует токенов и не вызывает API:

```bash
.venv/bin/python -m vpn_bot.migrate
```

Новые таблицы имеют префикс `vpn_`. Импорт переносит users (либо старые trial_users)
и payments в одной транзакции; исходные таблицы не удаляются и не обновляются.
Версия записывается после полного импорта. Повтор команды после успеха ничего не меняет.
Повреждённый тариф или конфликт уникальности прерывает импорт с rollback, включая DDL.
Строки trial_users с ID, уже представленным в users, считаются исторической копией.

UUID, email, port, срок, лимит и short_id сохраняются. Для исходной схемы main
sub_id восстанавливается по прежнему правилу `trial_` + последние 6 символов email.
Если в схеме есть явный sub_id, используется он. Отсутствующий short_id требует
ручной сверки, а не молчаливой замены ссылок. Уже существующие подписки не
перенастраиваются автоматически во время импорта.

Pending-платежи импортируются с привязкой к прежнему payment ID. Успешные и прочие
неоднозначные статусы, включая `succeeded`/`completed`, получают локальный `review`:
старые версии по-разному трактовали выдачу VPN. Оператор должен сверить платёж и
срок в панели, затем отдельно решить, требуется ли начисление. Автоматической
команды снятия review сейчас нет. Прежний провайдерский статус остаётся в исходной таблице.

Если БД содержит старую схему, обычный запуск откажется автоматически её менять.
Новая пустая SQLite/PostgreSQL БД создаётся при запуске приложения.
Команда миграции предназначена для импорта старой схемы внутри выбранной БД;
она **не переносит данные между SQLite и PostgreSQL**. Такой перенос требует
отдельного экспорта, проверки идентификаторов/связей и остановки записи на время переключения.

Откат версии приложения выполняйте вместе с восстановлением согласованной резервной
копии: после работы новой версии старые таблицы уже не отражают новые покупки.
