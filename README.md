# VPN Bot

Telegram-бот продажи VPN через ЮKassa и 3x-ui. Python 3.10+, aiogram 3,
aiohttp, SQLAlchemy 2. SQLite по умолчанию; PostgreSQL через asyncpg.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# Заполнить .env своими значениями.
.venv/bin/python main.py
```

Установщик и запуск используют одну `.venv`. Настройки проверяются при запуске,
импорт модулей не требует секретов. Тарифы сохранены из main в `vpn_bot/settings.py`:
1/3/6 месяцев, 1/3/5 устройств; деньги хранятся целыми копейками.

Новая БД создаётся при запуске. Для существующей БД сначала выполните
[миграцию](MIGRATION.md); старое приложение и новое не должны писать в неё одновременно.

| Настройка | Назначение |
|---|---|
| `API_TOKEN` | Токен Telegram из пользовательского хранилища секретов |
| `WEBHOOK_URL` | Внешний HTTPS URL Telegram webhook, например `/webhook` |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка из букв, цифр, `_`, `-` для проверки Telegram |
| `PUBLIC_URL` | Публичный HTTPS адрес бота для `/sub/{short_id}` |
| `DB_PATH` | Путь SQLite, используется при отсутствии `DATABASE_URL` |
| `DATABASE_URL` | `sqlite+aiosqlite:///...` или `postgresql+asyncpg://...` |
| `YOO_SHOP_ID`, `YOO_SECRET_KEY` | Реквизиты магазина ЮKassa |
| `YOO_RETURN_URL` | HTTPS адрес возврата, обычно ссылка на бота |
| `YOO_TEST_MODE` | `true` по умолчанию; ожидаемый test-флаг платежей магазина |
| `XUI_API`, `XUI_USER`, `XUI_PASS` | URL панели с base-path и реквизиты её API |
| `XUI_SUB_URL` | Полный HTTPS префикс подписок панели, включая `/sub` |
| `XUI_VERIFY_SSL` | `true` по умолчанию; отключение только для контролируемого стенда |
| `WEBAPP_HOST`, `WEBAPP_PORT` | По умолчанию `127.0.0.1:8443` за HTTPS reverse proxy |

В магазине ЮKassa настройте уведомления `payment.succeeded`, `payment.canceled`,
`payment.waiting_for_capture` на `https://<ваш-домен>/payments/yookassa`.
Приложение создаёт одностадийные платежи банковской картой (`capture=true`).
Наличие банковского метода и настройки чеков проверяются в конкретном магазине;
формирование `receipt`, возвраты и автосписания в этой реализации отсутствуют.

## Поведение

- Сначала сохраняется заказ, затем создаётся платёж с устойчивым ключом идемпотентности.
  Повтор нажатия в том же меню и повтор после timeout используют прежний заказ.
- Webhook и кнопка проверки обращаются к одному сервису; данные уведомления сами по
  себе не подтверждают оплату. Чужой callback отклоняется до обращения к ЮKassa.
- Оплаченные дни начисляются один раз. Раннее продление сохраняет остаток;
  истёкшая подписка продлевается от текущего времени. Лимит устройств заменяется тарифным.
- Фоновая сверка через 30 секунд после каждого прохода восстанавливает незавершённые
  оплаты и настройку панели. Профиль и уведомление показывают фактическое состояние.
- Пробная подписка — 3 дня, один раз. Новые короткие ссылки случайные; старые
  ссылки и идентификаторы сохраняются миграцией. Истёкшая/отключённая подписка не проксируется.
- Кнопка «Закрыть» закрывает меню; уже созданный платёж не отменяется.

## Структура и проверки

`vpn_bot/domain.py`, `ports.py`, `services.py` — бизнес-логика и контракты;
`storage.py`, `migrate.py` — SQL и миграция; `integrations/` — ЮKassa и 3x-ui;
`transport/` — Telegram и HTTP; `app.py` — сборка зависимостей и жизненный цикл.
Старые корневые модули заменены пакетом, запуск `python main.py` сохранён.

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Для проверки PostgreSQL используйте **отдельную одноразовую тестовую БД**:
`PG_TEST_URL=postgresql+asyncpg://... .venv/bin/python -m pytest -q`.
Fixture удаляет таблицы `vpn_*` в этой БД. Без переменной используются временные SQLite-файлы.
HTTP-тесты запускают локальные имитаторы; внешние аккаунты и действующая панель не используются.

[Архитектура](ARCHITECTURE.md), [план](docs/plan.md), [окружения](docs/environment-plan.md).
Старые отчёты находятся в `docs/history/` и не являются результатами текущих проверок.

Перед развёртыванием нужен smoke-тест на установленной версии 3x-ui: адаптер рассчитан
на классический API `/panel/api/inbounds` и отдельный VLESS Reality inbound на пользователя.
Разные версии панели могут менять контракт; успешный HTTP-ответ дополнительно проверяется чтением.
Не используйте реквизиты из Git-истории: в старых файлах были значения, похожие на секреты;
их актуальность неизвестна, замените их, если они когда-либо были действительными.
