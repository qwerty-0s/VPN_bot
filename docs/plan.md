## Проверяемые критерии

- [x] Карточный платёж создаётся асинхронно; заказ и ключ идемпотентности сохраняются
  до обращения в ЮKassa, повтор не создаёт новое списание.
- [x] Callback проверяет владельца заказа. Webhook перепроверяет платёж через API:
  статус, сумму, валюту, магазин, test-флаг и привязку к заказу.
- [x] Конкурирующие подтверждения начисляют срок только один раз; продление
  начинается с max(текущий срок, сейчас). Сбой панели можно повторить после рестарта.
- [x] SQL и выбор драйвера изолированы от бизнес-логики; SQLite работает по умолчанию,
  PostgreSQL выбирается DATABASE_URL, контракты и транзакции одинаковы.
- [x] Старые users/payments переносятся явной идемпотентной миграцией без удаления
  оригиналов. Неоднозначные старые succeeded требуют ручной сверки, не начисляются снова.
- [x] Пробная подписка, меню, профиль, короткие ссылки и запуск python main.py работают.
- [x] Есть проверки ошибок, повторов, конкурентных покупок, миграции и HTTP-адаптеров.
- [x] ARCHITECTURE.md, инструкция запуска и handoff отражают фактическую реализацию.
